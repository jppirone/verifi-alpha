STEP 2: THE FRONT PAGE GATE
Plain answer: visitors must type a shared phrase once per browser tab session before any of the four pages shows. It stops casual visitors and search crawlers. It does NOT stop anyone who reads the page source, or who calls the backend functions directly.
What was built
- js/alpha-gate.js (new, 75 lines), copied from the pattern of the FightGhostJobs stage gate (read only): a classic script that hides the page, stores only a salted PBKDF2-SHA256 hash (310000 rounds), shows a small form. Differences from the stage gate: it remembers success in sessionStorage (this browser tab session only, as asked) instead of localStorage; it has no host check (so it also asks when a file is opened locally); the switch below.
- Loaded as the FIRST script in the head of index.html, candidate.html, employer.html and staff.html (right after the robots tag).
- Wording: title "Applitrust alpha"; "This is a private test site. Enter the access phrase you were given."; label "Access phrase"; button "Continue"; error "That phrase did not match."; while checking "Checking..."; no https "This page must be opened over https.". No em dash, none of verified, compliant, certified.
- The phrase: four ordinary lowercase words with hyphens, chosen with Node's crypto random from a 492 word list (a Write-created file kept outside the repository). Only the salt and hash are in the gate file. Strength: about 35.8 bits. Plain meaning: fine against a casual visitor; a determined person with the page's hash and a fast graphics card could try every combination in roughly weeks (rough estimate, not measured). It is a deterrent. A longer phrase is a one-prompt change if you want it.
